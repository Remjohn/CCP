# Draft Protocol — Making Laws Testable Through Micro-Scale Testing

**Purpose:** Every creative agent should DRAFT before COMMITTING. Drafting = running law tests at micro-scale before full generation. Small tests → small discoveries → compounded winning edges.

**Core Principle:** An agent that never tests never discovers. An agent that always generates at full scale pays full price for failures.

---

## The 3-Phase Draft Protocol

### Phase 1: MICRO-DRAFT (10% scale)

Generate ONE element — one question, one blueprint, one SoC sentence, one visual prompt.

```
MICRO-DRAFT PROCEDURE:
  1. Generate 1 element at the smallest atomic level
  2. IMMEDIATELY run ALL 4 Laws against it:
     - Law 1 (Saturation): Did all required inputs influence this element?
     - Law 2 (Mode):       Does this element have a clear T/V/R classification?
     - Law 3 (Compression): Does every word serve one emotional function?
     - Law 4 (Gate):        Would this pass the stage's specific authenticity test?
  3. IF any law fails → DIAGNOSE before generating more:
     - Which law failed?
     - WHY did it fail? (wrong input? mode confusion? compression leak? generic output?)
     - Adjust the approach BEFORE spending generation tokens on the full batch
  4. IF all laws pass → proceed to Phase 2
```

**Why this matters:** If the first element fails, generating 11 more identical failures wastes the entire generation cycle. One micro-draft catches the systemic error early.

### Phase 2: ATOMIC TEST LOOP (3-element sample)

After the micro-draft passes, generate 3 more elements and test the SYSTEM-LEVEL properties:

```
ATOMIC TEST LOOP:
  1. Generate 3 elements (total now: 4 including micro-draft)
  2. RUN these system-level checks:
  
  MODE DIVERSITY CHECK:
    "Are all 3 modes (T/V/R) represented across these 4 elements?"
    → YES = the system is producing dimensional tension → proceed
    → NO  = mode-monotone detected → recalibrate before continuing
    
  NOVELTY CHECK (Boredom Ban):
    "Has the system produced something SURPRISING in these 4 elements?"
    → Surprise = an element the system didn't predict it would generate
    → YES = creative edge detected → log it → proceed
    → NO  = the system is in echo mode → TRIGGER intuition extension
    
  PATTERN DIVERSITY CHECK:
    "Do these 4 elements use different structural patterns?"
    → Example: if all 4 questions start with "What if..." → structural monotony
    → Vary opening patterns, emotional arcs, reference types
```

### Phase 3: FULL GENERATION (with confidence)

Only after Phase 1 + Phase 2 pass:

```
FULL GENERATION:
  1. Generate the complete batch (12 blueprints, 5 questions, etc.)
  2. Law gates applied to the full batch (standard validation)
  3. Receipt generated with Phase 1/2 micro-test results recorded:
     
  DRAFT PROTOCOL LOG:
  ━━━━━━━━━━━━━━━━━━
  Micro-draft:      [PASS — element: "..." — all 4 laws passed]
  Atomic test:      [PASS — mode diversity: T:2/V:1/R:1 — novelty: YES]
  Full generation:  [12 elements — all law-governed]
```
