# H1 — Blueprint Orchestrator: First-Principles Implementation Architecture

**Pipeline Stage:** CCF Research Phase → Content Theme Generation (Blueprint Orchestrator → 12 content blueprints)  
**Laws Applied:** 4 Laws of Content Distillation  
**Target Skill:** `ccf-26/skills/ccf/research/blueprint-orchestrator/SKILL.md`  
**Target Command:** `ccf-26/commands/ccf-blueprint.md`  
**Related Skills:** `ccf-26/skills/ccf/research/archetype-mapping/SKILL.md`  
**Input:** H0 Question Output (`provocation_questions.json` + coach responses) + Soul DNA (`soul_values.json`) + Tribe DNA (`tribe_profile.json`) + Research Briefs  
**Output:** 12 emotionally typed, fusion-compressed content blueprints (`content_blueprints.json`)  
**Validation:** H1 Distillation Receipt (Required before SoC generation begins)

---

## System Overview: What H1 Actually Does

The Blueprint Orchestrator sits at the exact boundary between raw first-party signal and publishable content structure. It receives the H0 output — the coach's provocation question responses, generated by the Question Engineer (`ccf-26/skills/ccf/content/question-engineer/SKILL.md`) — and fuses them with the Soul DNA, Tribe DNA, and research briefs to produce 12 content blueprints.

**A blueprint is not a topic. A blueprint is a precise emotional configuration:** a specific thesis, delivered through a specific framework combination, targeting a specific emotional mode, with a declared vulnerability move that only this coach can execute.

The current pipeline produces 12 blueprints and validates them structurally (correct format, 3 fusion layers, archetypes present). It does not validate whether the blueprints are emotionally dense or emotionally generic — whether they require the coach's first-party identity or could have been generated for any coach in the niche.

The 4 Laws of Content Distillation close this gap.

## Section 1: Input Quality Standards (Fusion Saturation Protocol)

H1 is a fusion engine. It can only output density equal to its least saturated input. Before any blueprint is generated, every input layer must pass the **Fusion Saturation Gate**.

### Required Input Files & Quality Standards

| # | Input Source | File / Field | Minimum Quality Standard |
|:--|:------------|:-------------|:------------------------|
| 1 | **H0 Provocation Output** | `provocation_questions.json` — coach's responses to provocation questions (from `ccf-26/skills/ccf/content/question-engineer/SKILL.md`) | Must be ≥50 words each + ≥1 named specific detail per answer |
| 2 | **Soul Values** | `soul_values.json` — coach's absolute beliefs, named enemy, voice | Must contain ≥1 explicit ENEMY (what the coach actively opposes), ≥1 counterintuitive position |
| 3 | **Tribe Profile** | `tribe_profile.json` — audience pain, slang, unnamed feelings | Must contain ≥1 unnamed feeling (what the tribe experiences but can't articulate) |
| 4 | **Fresh Research Brief** | `research/fresh/` — timely, trend-adjacent intel | Must include ≥1 contrarian data point that challenges the coach's thesis |
| 5 | **Deep Research Brief** | `research/deep/` — evergreen mechanisms + psychology | Must include ≥1 mechanism (not just phenomenon — the underlying WHY) |
| 6 | **Interest Ratio** | 4 obsessive angles from `soul_values.json` | Must be specific (not "philosophy" — "the sunk cost psychology behind budgeting apps") |

### Saturation Gate (Pre-Generation Check)

Before Law execution begins, the system runs the following 3-question gate. Any NO answer halts generation and triggers a targeted collection prompt:

```
SATURATION GATE QUESTIONS:

1. "For each input layer, does it contain at least one data point
   SPECIFIC to THIS coach that COULD NOT appear in another coach's file?"
   → NO = INSUFFICIENT — the fusion has no first-party fuel
   → YES = PASS

2. "Does the tribe_profile contain an UNNAMED FEELING — something the tribe
   experiences but has never seen articulated publicly?"
   → NO = INSUFFICIENT — Recognition mode cannot be activated
   → YES = PASS

3. "Does the research brief contain a CONTRARIAN FINDING — data or evidence
   that challenges what the audience currently believes?"
   → NO = INSUFFICIENT — Tension mode cannot be activated
   → YES = PASS
```

**If any gate fails:** The system halts and sends a targeted prompt back toward the relevant data source (H0 re-collection, soul values update, or research brief refresh). No blueprints are generated on insufficient inputs.

## Section 2: Law Execution Protocol

### Law 1 — Fusion Saturation Before Ideation

**Axiom:** *A content idea can only be as emotionally dense as its least saturated input layer.*

**What it does:** Tags every qualifying element from each input layer with its emotional mode BEFORE fusion begins. This creates a pre-ideation emotional map the Blueprint Orchestrator draws from.

**Execution:**

```
FOR EACH input layer (H0 answers, soul_values, tribe_profile, research briefs):

  Tag each qualifying element as:
  TENSION (T) — breaks the audience's mental model, documents the enemy
  VULNERABILITY (V) — exposes the coach at real cost, documents personal contradiction  
  RECOGNITION (R) — names what the tribe feels but can't articulate

  Minimum coverage required before fusion:
  ≥4 T-tagged elements | ≥4 R-tagged elements | ≥3 V-tagged elements
```

**Output of Law 1 — Pre-Fusion Emotional Map:**
```json
{
  "saturation_map": {
    "TENSION": [
      "soul_values: 'hustle culture is designed to keep you mediocre'",
      "research/fresh: 82% of budgeting app users relapse to previous habits in 6 weeks",
      "tribe_profile: they follow the 'net worth millionaires' who validate avoidance behavior",
      "H0_provocation_response_1: 'I tried every system on the market before building my own'"
    ],
    "VULNERABILITY": [
      "H0_provocation_response_2: 'There was a 6-month period I didn't open my own financial dashboard'",
      "soul_values: 'I used to be the advisor recommending what I secretly doubted'",
      "tribe_profile: the shame of posting about abundance while checking savings anxiety"
    ],
    "RECOGNITION": [
      "tribe_profile: 'they say they want simplicity but design complex systems to avoid deciding'",
      "H0_provocation_response_3: 'My clients delete the app because it fights who they ARE'",
      "research/deep: sunk cost psychology in personal finance — the effort justification loop"
    ]
  }
}
```

> [!IMPORTANT]
> 11 V-tagged elements or fewer is a Vulnerability deficit. It means the coach hasn't exposed enough. The system prompts for a second H0 collection round targeting Vulnerability specifically.

### Law 2 — 3-Mode Emotional Classification

**Axiom:** *A content idea's viral potential is proportional to the number of irreducible emotional triggers it activates. There are exactly 3.*

**What it does:** Every blueprint receives a PRIMARY mode tag and is tested for SECONDARY mode activation. The 12-blueprint batch is then validated for mode diversity.

**Mode Routing (22-Framework Affinity):**

| Mode | The Blueprint Makes the Audience... | Framework Affinity |
|:-----|:------------------------------------|:-------------------|
| **TENSION (T)** | "Wait — I never thought about it that way" | Fear/Insecurity, Controversial & Surprising, Dopamine Cliff, Conceptual Contrasts, Pattern Interrupt |
| **VULNERABILITY (V)** | "You're human like me — you struggled too" | Cautionary Tales, Emotional Triggers, Descriptive/Explanatory, Confessional |
| **RECOGNITION (R)** | "That's exactly what I feel but couldn't say" | Relatable Concerns, Reflective/Insightful, Practical Value, Top Reliable List |

**Mode Diversity Requirement:**

```
MINIMUM BATCH COVERAGE:
  ≥3 T-primary blueprints
  ≥3 V-primary blueprints
  ≥3 R-primary blueprints
  ≥3 multi-mode blueprints (primary + secondary activated)

FAIL STATE:
  8+ blueprints in TENSION, 0 in VULNERABILITY = emotional monotone batch.
  The audience builds INFORMATION without emotional PERMISSION to change.
```

**The mode tag is not cosmetic.** It is the instruction to every downstream agent. When the SoC Generator (`ccf-26/skills/ccf/production/soc-generator/SKILL.md`) receives a V-primary blueprint, it knows to surface personal cost stories. When the Art Director (`ccf-26/skills/ccf/distribution/art-director/SKILL.md`) receives a T-primary blueprint, it knows to surface documentary and archival visual references (documentation of the enemy). The tag carries intent across the entire pipeline.

### Law 3 — Fusion Compression, Not Framework Stacking

**Axiom:** *A content idea's density increases when its framework layers INTERACT across emotional modes, not when they merely coexist.*

**What it does:** Tests each blueprint's 3-layer fusion for compression density. Stacked frameworks (additive) fail. Compressed frameworks (interdependent) pass.

**The Compression Test (applied to every blueprint):**

```
FOR EACH blueprint, apply the COLLAPSE TEST:
"Remove any ONE of the 3 fusion layers. Does the idea COLLAPSE or just get weaker?"

THIN FUSION (fails — layers are additive):
  "5 Wealth-Building Strategies Every Investor Needs"
  Layer 1: {Practical Value} — a useful list
  Layer 2: {Top Reliable List} — still a useful list
  Layer 3: {Broad Appeal} — now just bigger
  RESULT: Remove Layer 3 → idea still works. Layers are substitutable. REJECT.

DENSE FUSION (passes — layers are interdependent):
  "The Net Worth Number That Made Me Feel Like a Fraud"
  Layer 1: {Cautionary Tales}(V) — coach's personal financial contradiction
  Layer 2: {Reflective/Insightful}(R) — the tribe's unnamed feeling: success as imposter
  Layer 3: {Controversial & Surprising}(T) — the achievement system incentivizes the fraud feeling
  RESULT: Remove Layer 2 → the V and T have no bridge. The idea collapses.
           Only THIS coach can connect their personal story (V) to the tribe's feeling (R)
           to the systemic critique (T). PASS.
```

**Cross-Mode Density Bonus:**  
The most compressed blueprints activate 2-3 modes in a single fusion. When Layer 1 is V-primary, Layer 2 is R-primary, and Layer 3 is T-primary, the collapse test becomes the proof: none of the three layers can be removed because each carries a mode the others don't.

**The Dense Fusion Standard:**
> "This idea requires this coach's specific lived experience (V), their tribe's unnamed feeling (R), and a counterintuitive mechanism (T) — and NONE of these three elements can come from a competitor."

**Operationalized Collapse Protocol (3-Step — per blueprint):**

```
STEP 1 — REMOVE TENSION LAYER
  Read the blueprint WITHOUT the T-mode element.
  "Does this blueprint still challenge the listener's existing belief?"
  → YES = T was decorative (it didn't carry irreplaceable polarity) → FAIL
  → NO  = T was load-bearing (removing it makes the idea agreeable/safe) → PASS

STEP 2 — REMOVE VULNERABILITY LAYER
  Read the blueprint WITHOUT the V-mode element.
  "Does this blueprint still carry personal cost — something expensive to share?"
  → YES = V was filler (the idea works without the coach's skin in the game) → FAIL
  → NO  = V was load-bearing (removing it makes the idea impersonal) → PASS

STEP 3 — REMOVE RECOGNITION LAYER
  Read the blueprint WITHOUT the R-mode element.
  "Does this blueprint still make the tribe feel seen — 'how did you know?'"
  → YES = R was generic (the idea doesn't need THIS tribe) → FAIL
  → NO  = R was load-bearing (removing it makes the idea universal not tribal) → PASS

VERDICT:
  ALL 3 PASS = Blueprint is compressed. Each layer is irreplaceable. APPROVE.
  ANY 1 FAIL = Blueprint has fat. Regenerate the failing layer with higher specificity.
  2+ FAIL    = Blueprint is structurally weak. Return to Law 2 for mode re-assignment.
```

> [!IMPORTANT]
> This protocol is DRAFTABLE. Run it on a single blueprint at micro-scale before applying to the full batch of 12. If the first blueprint fails, the saturation map needs recalibration — don't waste generation cycles on the remaining 11.

### Law 4 — The Content Unpredictability Gate

**Axiom:** *A blueprint's value is inversely proportional to how many coaches in the same niche could produce it.*

**What it does:** Runs 4 authenticity checks on every blueprint before it is approved to proceed downstream. Blueprints that fail return to Law 3 compression.

```
CHECK 1: AI Sovereignty Test
  "Could an AI generate this blueprint without consuming soul_values.json?"
  → YES = REJECT — the idea doesn't require the coach's identity
  → NO  = PASS — the idea is identity-locked

CHECK 2: Competitor Non-Replication Test
  "Could a competitor in the same niche post this exact title without
   it being false advertising for their brand?"
  → YES = REJECT — no irreducible uniqueness
  → NO  = PASS — the idea is coach-specific

CHECK 3: Memory Access Test
  "Does the three_part_vulnerability_move require a SPECIFIC memory
   from the coach's actual life to execute authentically?"
  → NO  = REJECT — the vulnerability is performative, not felt
  → YES = PASS — first-party emotional data is required

CHECK 4: Tribe Recognition Test
  "Would a member of this tribe react with 'How did you know that about me?'
   to at least one element of the content_premise?"
  → NO  = REJECT — Recognition mode is absent or generic
  → YES = PASS — the specificity → universality bridge is operational
```

**Failed blueprint routing:** If 1-2 checks fail → return to compression (adjust layers). If 3-4 checks fail → the blueprint is structurally invalid and must be regenerated from the saturation map.

## Section 3: Output Format & Pipeline Delivery

After Law 4, approved blueprints are written to `blueprints.json` with the new required fields:

```json
{
  "blueprint_id": "BP01",
  "full_title": "The Net Worth Number That Made Me Feel Like a Fraud",
  "mode_primary": "VULNERABILITY",
  "mode_secondary": "RECOGNITION",
  "fusion_density": "COMPRESSED",
  "fusion_layers": {
    "base": { "framework": "Cautionary Tales", "mode": "V", "contribution": "Coach's personal contradiction" },
    "enhancement": { "framework": "Reflective/Insightful", "mode": "R", "contribution": "Tribe's unnamed imposter feeling" },
    "amplification": { "framework": "Controversial & Surprising", "mode": "T", "contribution": "System incentivizes the fraud feeling" }
  },
  "three_part_vulnerability_move": {
    "felt": "I remember the exact number where I felt like a fraud",
    "did": "I stopped looking at the dashboard for 6 months",
    "results": "That was the most financially clear period of my career"
  },
  "unpredictability_gate": {
    "ai_test": "PASS",
    "competitor_test": "PASS",
    "memory_test": "PASS",
    "tribe_recognition_test": "PASS"
  },
  "downstream_routing": "SoC-V-primary → Art-Director-Vulnerability → Visual-Recipe-VULNERABILITY"
```

> [!IMPORTANT]
> The `downstream_routing` field is new. It carries the mode instruction to every subsequent CCF pipeline stage — SoC Generator (`production/soc-generator/`), Art Director (`distribution/art-director/`), Visual Recipes (`distribution/visual-recipes/`) — so that emotional mode coherence is maintained across the full funnel without each downstream agent having to re-derive it.

## Section 4: Evaluation — 5 Micro-Hypothesis Tests

Before blueprints are passed to the SoC Generator (`ccf-26/skills/ccf/production/soc-generator/SKILL.md` via `ccf-26/commands/ccf-soc.md`), the following 5 micro-hypotheses are tested against the full batch of 12.

### MH1 — The Mode Diversity Test
**Hypothesis:** "The 12 blueprints cover all 3 emotional modes with no mode representing more than 60% of the batch."  
**Test:** Count blueprints by primary mode: T-count, V-count, R-count, multi-count.  
**Pass condition:** No single mode accounts for >7/12 blueprints. Multi-mode blueprints count toward their primary mode only.

### MH2 — The Collapse Density Test
**Hypothesis:** "At least 8 of the 12 blueprints produce a complete idea collapse when any single fusion layer is removed."  
**Test:** Apply the Collapse Test to every blueprint. Categorize: COMPRESSED vs ADDITIVE.  
**Pass condition:** ≥8/12 blueprints are COMPRESSED (complete collapse under single-layer removal). If fewer than 8 pass, return the failing blueprints to Law 3.

### MH3 — The First-Party Irreducibility Test
**Hypothesis:** "Every blueprint contains at least one element that requires THIS coach's specific lived experience to execute."  
**Test:** Isolate the `three_part_vulnerability_move.felt` field from every blueprint. Could any version of this sentence have been written by a different coach in the same niche?  
**Pass condition:** 100% of vulnerability moves reference a specific, datable memory (a specific time period, number, decision, or conversation) that is irreducibly the coach's own.

### MH4 — The Downstream Utility Test
**Hypothesis:** "Every approved blueprint carries enough mode clarity that the SoC Generator (`production/soc-generator/`), Art Director (`distribution/art-director/`), and Visual Recipes (`distribution/visual-recipes/`) can execute against it without needing to re-interrogate the coach."  
**Test:** Check that every blueprint has: `mode_primary`, `mode_secondary` (if multi-mode), `fusion_density`, and `downstream_routing` fields populated.  
**Pass condition:** 100% of blueprints are fully tagged. Downstream handoff requires zero re-interpretation by the receiving agent.

### MH5 — The Saturation Traceability Test
**Hypothesis:** "Every blueprint contains at least one element that traces directly to the H0 provocation output — the coach's answers to provocation questions delivered via Telegram bot."  
**Test:** For each blueprint, identify which element of the `content_premise` or `three_part_vulnerability_move` originates from the coach's responses to `provocation_questions.json`. Map the lineage.  
**Pass condition:** ≥10/12 blueprints have a traceable H0 element. If <10, the Blueprint Orchestrator is generating ideas INDEPENDENTLY of the coach's session — meaning the Distillation Funnel has a break in its chain.

## Architectural Constants

| Constant | Value | Rationale |
|:---------|:------|:----------|
| Blueprints generated | 12 | CCF content cycle — 12 themes covers all 4 mode archetypes × 3 formats |
| Mode diversity minimum | 3T + 3V + 3R + 3 multi | Prevents emotional monotone batch; ensures full audience coverage |
| Compressed blueprints required | ≥8/12 | Dense ideas outperform thin ideas; system enforces quality at generation |
| Unpredictability gate checks | 4 | Mirrors H0's 4-check gate — parallel architecture across funnel |
| Vulnerability moves required | 100% of blueprints | Every piece requires the coach's personal stake — no generic content |
| H0 traceability required | ≥10/12 | The funnel is closed-loop: coach input must flow into every output |
