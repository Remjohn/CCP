## 2. Overview

### Problem Statement
A perfectly engineered emotional trigger delivered to the wrong psychological mode does not just underperform—it actively damages the coach-audience relationship (e.g., serving heavy, high-arousal processing content to an exhausted audience member seeking escape). Previously, the CCP generated content based purely on topical relevance and voice matching, lacking a mechanism to adjust message delivery to the audience's immediate cognitive and emotional capacity. 

### Solution
FR18 implements the **Psychological Routing Brief Generator (DEP-ENG-016)**. This engine executes before template selection in the compilation pipeline. It ingests the audience's current Live Psychometric Feed and Mood Context Map, cross-referencing them against established psychological frameworks to compute an 8-variable instruction set. This instruction set is injected directly into `Block B (field_3_context)` of the compilation, forcing the downstream generation agent to structurally adapt the content (e.g., masking a payload in humor, shifting from a gain-frame to a loss-frame) based on the audience's neurological state.

### Scope
**In scope:**
- Stage 1: Ingestion of `DEP-ENG-018` (Mood Context Map) and `DEP-ENG-017` (Audience Maturity Profile).
- Stage 2: Resolution logic for the 8 core psychological variables.
- Stage 3: Compilation of the `DEP-ENG-016` object JSON payload.
- Cryptographic Receipt Chain Guard checks at each transition.

**Out of scope:**
- Trigger execution (FR15).
- Block C validation.

| **Mood Management Theory** | Zillmann | 1988 | `arousal_direction` / `valence_delivery` |

### Technical Decisions
1. **Deterministic Mapping:** Variables are mathematically resolved based on the input arrays; they are NOT inferred by an LLM guessing at "vibe". See Section 4 for explicit matrix tables.
2. **Payload Masking Injection:** The generator outputs a literal `payload_masking_instruction` string that is directly glued into the Emilio prompt to force structural Trojan Horse behavior.

## 4. Implementation Plan

### Stage 1: State Ingestion
*Agent Name:* Psych-Routing-Engine
*Inputs:* `DEP-ENG-018`, `DEP-ENG-017`.
*Outputs:* Working variables.
*Failure Condition:* Inputs missing essential metrics (e.g., maturity cohort undefined).

**Steps:**
1. Fetch the active batch slot parameters.
2. Load the Audience Maturity (New/Developing/Loyal) and the active Mood State vector (Arousal/Valence quadrant).

  stage_name: 'STAGE-1-ROUTING-INGEST',

  timestamp }

### Stage 2: Variable Resolution Matrix
*Agent Name:* Psych-Routing-Engine
*Inputs:* Working variables.
*Outputs:* Resolved ENUM values.
*Failure Condition:* Null exception on matrix lookup.

**Decision Logic (Enum Production):**

1. **`mood_state_primary`**
   - *Logic:* Fetched directly from the batch composer allocation slot assigned to this specific run.
   - *Enums:* `[Processing, Escape, Discovery, Status]`

2. **`arousal_direction`**
   - *Logic:* Inversely mapped to audience current state.
   - *If* audience arousal == HIGH -> Enum `<lowers>`
   - *If* audience arousal == LOW -> Enum `<raises>`
   - *If* Mood = Discovery -> Enum `<maintains>`

3. **`valence_delivery`**
   - *Logic:* Computes the necessary emotional polarity/atmosphere based on the primary mood state.
   - *If* Escape -> Enum `<positive>` (Humor, calming, relief)
   - *If* Discovery -> Enum `<positive>` (Curiosity, expansive, awe)
   - *If* Status -> Enum `<mixed>` (Aspirational, comparison-oriented)
   - *If* Processing -> Enum `<eudaimonic>` (Heavy, meaningful, contemplative)

4. **`regulatory_frame`**
   - *Logic:* Mapped to audience language markers (LIWC-22 inferred from `DEP-ENG-018`).
   - *If* audience is gain-seeking -> Enum `<promotion>`
   - *If* audience is threat-avoidant -> Enum `<prevention>`

4. **`sdt_need_primary`**
   - *Logic:* Bound 1:1 to the primary mood state.
   - *If* Escape -> Enum `<relief>`
   - *If* Discovery -> Enum `<competence>`
   - *If* Status -> Enum `<autonomy>`
   - *If* Processing -> Enum `<relatedness>`

5. **`sequencing_dependency`**
   - *Logic:* Bound to Discovery mode constraint.
   - *If* Discovery -> Enum `<requires_positive_prime>`
   - *Else* -> Enum `<independent>`

6. **`comparison_type`**
   - *Logic:* Evaluated only if Mood State == Status. Drives social proof mechanics.
   - *If* Status + New Cohort -> Enum `<upward_assimilation>`
   - *If* Status + Dev/Loyal -> Enum `<worldview_validation>`
   - *Else* -> Enum `<none>`

7. **`tmt_function`**
   - *Logic:* Evaluated only if Mood == Processing. Determined by Audience Maturity.
   - *If* Processing + Loyal Cohort -> Enum `<worldview_construction>`
   - *If* Processing + New/Dev Cohort -> Enum `<insight_delivery>`
   - *Else* -> Enum `<none>`

8. **`semantic_affinity_risk`**
   - *Logic:* Mapped dynamically during batch lock (handled upstream), dictates if domain swap is required.
   - *Provided as pass-through* `<low/medium/high>` from `DEP-ENG-018` Pain Map collision test.

- Receipt Write: Per FR47 DEP-ENG-041 schema —
{ receipt_id, previous_receipt_hash,
  input_payload_hash, output_payload_hash,
  stage_name: 'STAGE-2-VARIABLE-MATRIX',
  agent_name: 'Psych-Routing-Engine',
  timestamp }

### Stage 3: Payload Construction & Emit
*Agent Name:* Psych-Routing-Engine
*Inputs:* Resolved Enums.
*Outputs:* `DEP-ENG-016` (Psychological Routing Brief JSON).
*Failure Condition:* Brief object fails schema typing validation.

**Steps:**
1. Dynamically fetch the appropriate `payload_masking_instruction` string based on `mood_state_primary`.
2. Construct final JSON schema.
3. Receipt Write: Per FR47 DEP-ENG-041 schema —
{ receipt_id, previous_receipt_hash,
  input_payload_hash, output_payload_hash,
  stage_name: 'STAGE-3-ROUTING-EMIT',
  agent_name: 'Psych-Routing-Engine',
  timestamp }
4. Pass payload to Block B of the compilation template.

## 6. Backward Compatibility Fallback
If `DEP-ENG-018` (Mood Context Map) is unavailable (e.g., LIWC-22 API outage or fresh account setup with no data):
1. The engine falls back to a **Neutral Processing Proxy State**.
2. Arousal = `maintains`, Regulatory = `promotion`, Semantic Risk = `lowered_by_default`.
3. An `OPERATOR_WARNING` flag is tripped indicating the brief is running via static defaults rather than live psychometric reading. 
4. Compilation continues normally, relying entirely on the coach's `DEP-ENG-005` TTT profile.

## 8. Acceptance Criteria

- [ ] **AC1 (Zillmann Arousal Modulator):** Given a `DEP-ENG-018` state of "HIGH Arousal / Negative (Stressed)", the script returns the `arousal_direction` enum `<lowers>`. *Failure Example:* The system routes `<raises>` causing the downstream script to generate high-energy hype content to a completely burnt-out reader.
- [ ] **AC2 (TMT Cohort Guard):** Given a `mood_state` of `Processing` and an audience cohort of `New (0-4wk)`, the system calculates the `tmt_function` as `<insight_delivery>`. *Failure Example:* The system outputs `<worldview_construction>`, pushing heavy existential indoctrination onto day-1 followers.
- [ ] **AC3 (SDT Validation):** Given a `mood_state` of `Discovery`, the system unequivocally returns `sdt_need_primary: <competence>`. *Failure Example:* Returning `<relatedness>` forcing the generator agent to write an emotional connection piece when the format requires objective, competence-building observation.
- [ ] **AC4 (ADR-01 Strict Isolation):** The engine reads `DEP-ENG-017` maturity profiles exclusively from the coach's private isolated storage container. *Failure Example:* The engine reads a global platform average maturity timeline and misclassifies the audience depth parameters.

## 10. Testing Strategy

### Unit Tests
- **Matrix Enum Resolution:** Feed the resolution function 8 mock states spanning all edge cases (e.g. `Escape + Low Arousal`, `Status + Dev Cohort`). Assert that all 8 variables resolve to the exact mathematically expected strings without throwing enum domain errors.
- **Graceful Fallback Logic:** Execute the module with entirely NULL upstream parameters. Assert the fallback state is triggered emitting `Neutral Processing Proxy State` strings and raising the `OPERATOR_WARNING`.

### Integration Tests
- **Brief Injection:** Hook the output of this module into the Builder Engine integration staging pipeline. Assert the final generated `SKILL.md` Block B successfully contains the emitted JSON block precisely nested under `field_3_context`.
- **Payload Masking String Test:** Trigger `Escape` mode. Retrieve the final generation prompt payload. Use regex matching to verify the explicit literal string `"The truth is the punchline, not the lesson"` is present in the prompt context window.

### Safety Tests (ADR-01 & Receipt Isolation)
- **Tenant Context Bleed Check:** Initiate the router simultaneously for Coach A and Coach B. Verify via the cryptographic receipts that Coach A's maturity profile variables were never cross-referenced during Coach B's matrix evaluation.
