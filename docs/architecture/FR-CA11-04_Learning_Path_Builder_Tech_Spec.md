## 2. Overview

### Problem Statement
The CCP generates enormous volumes of coaching content: 36 weekly CCF scripts, V²WS webinar recordings, CBCS voice notes, OBS session recordings, Excalidraw diagrams. But this content is produced for *broadcasting* — it's designed to attract the coach's audience on social media. There is no mechanism to retroactively organize this content into *structured educational journeys* for paying coaching clients. Coaches manually create courses by copying content into Google Drive or Kajabi — a process that takes 10-20 hours per course and completely bypasses CCP's intelligence.

### Solution
FR-CA11-04 implements the **Continuous Learning Path Builder** — a dedicated agent (`Gabrielle`) that automatically categorizes every piece of content generated by any CCP pipeline (CCF, V²WS, CBCS, OBS, CMF) by topic cluster, difficulty level, program tag, and content type. These categorizations are stored in the `learning_path_registry` Supabase table, and the content is organized into visual learning timelines displayed in the client's AFFiNE workspace. The coach never manually "creates a course" — the course builds itself from their natural production.

### Scope
**In scope:**
- `learning_path_registry` Supabase table design.
- `Gabrielle` agent skills: content classification, journey construction, next-content recommendation.
- Learning path timeline visualization data structure (consumed by Excalidraw rendering in FR-CA11-09).
- Integration hooks: CCF batch completion, V²WS webinar completion, OBS session recap (FR-CA11-05), voice note lesson (FR-CA11-06).

**Out of scope:**
- Client workspace rendering of learning paths (FR-CA11-03).
- Excalidraw chart rendering (FR-CA11-09).
- Content gating enforcement (FR-CA11-03 via `Noémie`).

## 3. Context for Development

### Architecture Traceability

|---|---|---|

| `DEP-ENG-040` | Universal Asset ID | KEY — Each content entry in `learning_path_registry` links to a Universal Asset ID. |

### Academic Grounding

| Framework | Author | Year | Mechanism |
|---|---|---|---|
| **Spaced Repetition** | Ebbinghaus (1885), Pimsleur (1967) | 1885/1967 | Learning paths sequence content with optimal spacing between related concepts — not cramming everything linearly. |
| **Constructive Alignment** | Biggs | 1996 | Content is categorized not just by topic but by intended learning outcome (awareness → understanding → application → mastery), aligned with the ICT 5-position model. |

### Technical Decisions
1. **Topic Cluster via Context Premise Map:** Instead of inventing a separate taxonomy, Gabrielle maps content to the existing 12-dimension Context Premise Map (Fears, Enemies, Dreams, Hidden Beliefs, etc.). This aligns learning content with the same psychological framework that drives CBCS and CPSC — the learning journey mirrors the transformation journey.
2. **Difficulty Level = Audience Maturity:** Content difficulty maps directly to the Audience Maturity Lifecycle (FR20): New (surface-level), Developing (intermediate), Loyal (deep). This reuses existing infrastructure rather than creating a parallel classification system.
3. **Journey Construction Algorithm:** Learning paths are constructed as directed acyclic graphs (DAGs) where prerequisites define ordering. A "Mindset Foundations" node must be completed before an "Advanced Reframing" node. The DAG is stored in Neo4j (extending the existing graph infrastructure) and rendered as a visual timeline in Excalidraw.

## 4. Implementation Plan

### Stage 1: Registry Table & Classification Logic
*Agent:* `Gabrielle` (Learning Path Agent)
*Inputs:* Content piece (script, video, voice note, diagram) + metadata (Fingerprint ID, Asset ID, Context Premise).
*Outputs:* `learning_path_registry` entry.

**Steps:**
1. Create `learning_path_registry` Supabase table with schema:
   - `content_id` (UUID, PK)
   - `asset_id` (text, FK → Universal Asset ID)
   - `fingerprint_id` (text, FK → Fingerprint Archive)
   - `coach_id` (UUID)|
   - `content_type` (enum: `script`, `video`, `voice_lesson`, `webinar`, `session_recap`, `diagram`, `course_video`, `course_chapter`)
   - `topic_cluster` (text) — mapped from Context Premise Map dimensions
   - `difficulty_level` (enum: `new`, `developing`, `loyal`)
   - `program_tag` (text, nullable) — coach's program identifier
   - `journey_id` (UUID, nullable) — which learning journey this belongs to
   - `sequence_position` (integer, nullable) — position within the journey
   - `created_at` (timestamp)
   - `unlock_condition` (JSONB) — gating rules (consumed by `Noémie`)
2. Implement classification logic in `Gabrielle`:
   - Extract topic cluster from Content Premise Map dimensions that were active during content generation (available via the Fingerprint ID → Psychological Routing Brief trace).
   - Map difficulty level from the `audience_maturity_profile` that was active during generation.
   - Auto-assign `program_tag` if the content was generated within a specific program context.

### Stage 2: Journey Construction
*Agent:* `Gabrielle` (Learning Path Agent)
*Inputs:* Accumulated `learning_path_registry` entries for a coach.
*Outputs:* Journey definitions (DAG nodes and edges) stored in Neo4j.

**Steps:**
1. Group `learning_path_registry` entries by `topic_cluster`.
2. Within each topic cluster, order by `difficulty_level` (new → developing → loyal) and `created_at`.
3. Create Neo4j journey graph: each content piece is a node, edges define recommended sequence.
4. Apply prerequisite logic: "Foundations" difficulty content must appear before "Developing" content in the same topic cluster.
5. Store `journey_id` and `sequence_position` back to `learning_path_registry`.
6. Write Receipt Chain Guard entry per FR47 DEP-ENG-041 schema.

### Stage 3: Next-Content Recommendation
*Agent:* `Gabrielle` (Learning Path Agent)
*Inputs:* Client's completed content nodes, current coping position, atlas week.
*Outputs:* Recommended next content piece (pushed to client dashboard via FR-CA11-02).

**Steps:**
1. Query the journey graph for the client's current journey.
2. Identify completed nodes (tracked in `learning_progress` table: `client_id`, `content_id`, `completed_at`).
3. Traverse DAG to find next uncompleted node whose prerequisites are all complete.
4. Filter by gating rules (coping position, atlas week).
5. Return recommended content with preview text.

## 6. Backward Compatibility Fallback
If `Gabrielle` fails to classify a content piece (missing Context Premise data, unrecognized format), the content is still delivered to the coach's AFFiNE workspace via the standard Sync Service (FR-CA11-02). It simply doesn't appear in learning paths until manually classified by the operator or until Gabrielle retries with enriched metadata.

## 10. Testing Strategy

### Unit Tests
- **Classification Accuracy:** Pass 5 known content pieces with known Fingerprint IDs. Assert correct topic cluster and difficulty level assignments.
- **DAG Construction:** Build a journey from 8 ordered content pieces. Assert prerequisite edges form a valid DAG (no cycles).

### Integration Tests
- **End-to-End Pipeline:** Run CCF batch → assert 36 entries in `learning_path_registry` → assert journey graphs updated in Neo4j → assert client dashboard shows updated learning path.

### Safety Tests
- **Coach Isolation:** Attempt to insert a content piece from Coach A into Coach B's learning path. Assert the registry validates `coach_id` and rejects the cross-tenant write.
